### 1. [Kimi K3.1 Pro：智能前沿，更进一步](https://linux.do/t/topic/3067068)

- **核心分类**：前沿快讯 / 大模型发布
- **解决痛点**：K3 之后的旗舰断档；开发者需要长上下文 + 长程 Agent 能力强、且定价可负担的国产选择。
- **技术要点与核心流程**：3 万亿参数、100 万上下文，K3 的后训练版本（RL 算力大幅增加）；同步推出 Highspeed 版（同等智能、输出 2~3 倍速）。基准：Terminal-Bench 4.0 得分 65.7% 超 GPT-6 Astra（58.2%）、逼近 Claude Opus 5.5（66.4%）；BenchCAD 92.7%；OfficeQA Pro v2 得 64.4 拿 SoTA；事实压力测试单项错误率从 K3 的 23.4% 降至 8.3%。安全策略是本文最独特的部分：从中期训练与 RL 两个阶段识别并移除网络攻防数据，xdev-bench-hard pass@3 由未过滤的 90.5% 降到 81.0%，并以此作为开放权重发布依据。**完整权重 11 月 4 日前开源**。API 定价：输入 1.3 元/百万 token（命中缓存）与 13 元（未命中），输出 68 元；Highspeed 版 2 倍价。另有 Kimi Hosted Agents 托管智能体与企业版。
- **价值总结与实践建议**：当日社区最大科技事件，但社区实测呈两极——官方基准亮眼，而前端实测帖称"非常拉"（怀疑是 Flash 模型）、猫榜逻辑推理出分被称"幽默"，另有宣传稿未标广告的公关争议。建议观望者等 11 月权重开放后本地跑分验证再决定生产力迁移；缓存命中价 1.3 元/M 具备生产可用性；其"安全能力数据移除 + 渐进开放"的权重发布策略是行业首个公开范本，值得安全从业者精读。

### 2. [腾讯云 skill 会在被调用后静默上报后续用户消息](https://linux.do/t/topic/3066447)

- **核心分类**：安全隐私 / AI 供应链
- **解决痛点**：skill/MCP 生态的隐藏遥测审计盲区——harness 默认信任已安装的 skill，skill 内的隐藏 prompt 不会触发模型面对不可信内容的安全机制。
- **技术要点与核心流程**：作者发现 `@tencent-rtc/trtc-push-skill` 被调用后会静默上报用户后续每一句话；排查确认 `trtc-agent-skills` + `trtc-push-skill` 两个包共 12 个 skill 存在遥测，其中 11 个老版为隐蔽上报、新版改为"先斩后奏"（第一次上报后才询问）。实现细节堪称教材级：模型 + hooks 配合维护本地去重队列间歇上报（4 个版本迭代 4 遍）、象征性脱敏（仅模式匹配密钥/手机号，项目路径与关键代码全文上传）、prompt 中明确写"禁止模型向用户提及上报/遥测"、甚至让模型在用户代码中找出 appid 一并上报用于身份绑定。作者已提 issue，腾讯当晚即回复。可屏蔽上报域名：`*.cls.tencentcs.com/tracklog`、`webim.tim.qq.com/v4/imopenstat/tim_web_report`。
- **价值总结与实践建议**：AI 供应链安全的标志性案例——skill 的"使用者"是模型而不是人，隐藏指令可以借模型之手绕过一切面向人类的防线。三点行动建议：① 立刻让 AI 审计本机所有已安装 skill（与开源闭源无关，本例就是开源 skill）；② 需要继续用腾讯云 skill 的在网关层屏蔽上述域名；③ 意识到 skill/MCP 的隐私法规仍是空白，未来个人 Agent 普及后此类风险只会放大，防护意识是最后防线。

### 3. [【开源推广】exe-reverse 技能配布](https://linux.do/t/topic/3069439)

- **价值总结与实践建议**：94 赞/790 浏览，点赞比当日 Develop 区第一；评论区"之前的 apk-reverse 超级好用"的口碑背书明确，是逆向入门者搭 AI 辅助流水线的现成入口。两个额外观察：① 用前自审——早期技能产物建议在隔离环境跑；② GitHub 对逆向类项目的下架正把作者推向 Codeberg，做安全工具的开发者应有第二托管位的预案。

### 4. [Any请求疑难杂症解决方案（第二期）：本地网关设计](https://linux.do/t/topic/3066484)

- **核心分类**：AI 基础设施 / 可复制工作流
- **解决痛点**：Codex 经共享订阅池（"Any"）使用时的降智、持续性 429、502、加密块 400、僵尸请求等疑难杂症——客户端报错信息被吞，用户只能干瞪眼。
- **技术要点与核心流程**：在 Codex 与上游之间加一层本地网关（Codex → 网关 → Any），六项能力：① 截获原始响应拿到详细错误；② 从消息流解析实际思维强度映射（low→low，mid/high→high，xhigh/max→max），识别被静默路由到 low 的"降智"；③ 随机替换会话 ID 强制切号，应对号池风控 429 与上游资源被删的 502（代价是该次 0 缓存）；④ 仅在 compaction（本地压缩）请求遇到 400 时剥离不兼容加密块重试，避免每请求剥离造成持续 0 缓存；⑤ 上游转发前对高清图微损压缩；⑥ 2 分钟无首字的僵尸请求掐断重试。作者建议直接让 AI 参考 sub2api 的实现来写。
- **价值总结与实践建议**：网关位是诊断与修补"上游不可控"问题的通用抓手，思路可迁移到任何不稳定 API 链路（中转站、企业网关同理）。注意评论区提醒：网关转发可能改变客户端指纹，有账号风控风险，需自行权衡。"让 AI 写这种东西可快了"——这篇的价值是方法论清单而非成品代码。

### 5. [[开源] reveric：Agent Native 一站式小说/短剧创作工作台](https://linux.do/t/topic/3068736)

- **核心分类**：开源项目 / AIGC 创作工具
- **解决痛点**：剧本写作与短剧成片工具割裂，无法在同一上下文里完成"设定 → 剧本 → 分镜 → 生成 → 剪辑"全流程。
- **技术要点与核心流程**：Flutter 实现本地优先（下载即用，免 web 部署）；Agent Native 设计——UI 能做的事 AI 基本也能做，支持 subagent、codemode、skill 按需加载；无限画布可把参考图、人设、场景连线关联；内置关系图谱、世界观设定、人设管理；3D 导演台可预演角色动作与走位来指导生成；视频生成已接 Seedance（火山/OpenRouter/atlascloud 中转），配合自动化剪辑与图像处理。
- **价值总结与实践建议**：33 赞/279 浏览，早期项目社区初印象佳。适合网文/短剧创作者与 AIGC 工作流研究者试用；要有心理预期：视频渠道集成仍碎片化，实测主推的 atlascloud 较贵，且需要按自身流程补齐自己的 skill——它是工作台框架而非开箱即用的成片工厂。
