### 3. [不反代、不封号：反重力antigravity使用acp协议实现完美嵌入到deepseek harness中使用](https://linux.do/t/topic/3133812)

- **核心分类**：Develop / Agent 客户端协议与工具链接入
- **解决痛点**：Antigravity 客户端很难用（硬截断、频繁重试、location 限制、交互抽象、无上下文显示、subagent 不好用），「模型实力属实是受到 antigravity 的克制了」，所以很多佬把它反代出来用；但最近封号程度大幅增加。作者要解的是「既摆脱垃圾客户端在别的 harness 里用，又能保证不被封号」。
- **技术要点与核心流程**：答案是 **ACP（Agent Client Protocol）**——`agy acp` 启动一个 ACP server，让支持 ACP 的编辑器 / harness 把 Antigravity CLI 当 coding agent 调用。关键在于它**本质是拉起一个 agy cli 进程来交互，并非用 auth 鉴权直接对 API 端点发请求**，且 agy acp 是谷歌官方开放的使用方式，因此不落在「反代」那一类。相比把 agy 当 subagent（黑盒），ACP SDK 能看到 tps、token 使用情况、额度，还能控制思考强度、传参微调，让 Gemini Argon 作为主 agent。作者据此写了接入 DeepSeek Harness 的插件（`lili-luo/dsh-plugin-bundle`）：对话 UI 内优先看周限额而非 5 小时限额；自由调上下文长度与思考强度（256K=1.0 倍率 / 512K=1.3 / 900K=1.8，作者认为 512K 是甜点倍率）；解锁 Claude / GPT 系模型（最新消息称更新最新版 agy 即可解除）；完整 UI 可见 tps / 缓存（谷歌缓存约 3–15 分钟、多数 5 分钟，「基本是没有缓存」，插件缓存处理仍待完善）/ 真实上下文占用；subagent 可完美调用、「和 api 一样是一等公民」。上下文解锁脚本在 `dsh-plugin-bundle/agy-context-unlock`，并引用了自己此前那篇 256K 硬编码封顶逆向帖。开发协作心得：用 Gemini 4 Argon 规划写文档、DeepSeek Flash 4.1 作 subagent 执行。
- **价值总结与实践建议**：3,746 浏览 / 301 赞 / 119 回复，是当天技术区最扎实的一帖。回复里 @newwangshaofeng 问「有没有办法基于这个 acp 协议搞个 2api」，作者明确回「不行的，这个本质上还是拉 agy cli 去调用，和 2api 本质上原理是不一样的，不是一码事」；@imgdo 泼冷水「本身Gemini现在模型就不行，我说句不好听的」。三点如实说：① 「不反代、不封号」是**作者对自己 20x 账号的体感**（「使用下来体感个人感觉和反代的没有任何差别，而且还十分稳定」），不是平台承诺——ACP 只是调用路径不同，订阅条款与风控规则并没有因此改写，别把它当成免封保证；② 上下文 256K/512K/900K 与 1.0/1.3/1.8 倍率来自作者此前的逆向，**需要改闭源二进制解锁**（他给的脚本要「直接发给 AI 让他使用」），客户端一升级就可能失效，也可能违反服务条款；③ 值得肯定的是思路本身——用官方公开的协议把 Agent 接进自己顺手的 harness，比维护一套反代更可持续，@newwangshaofeng 想再包一层 2api 恰恰会把它退回老路。
