### 1. NexKr 韩国 SKB 家宽产品测评：用 IPERF3 把「半优化」「看脸」「假延时」讲透

- **核心分类**：Develop / 资源测评 · 家宽落地机（VDS）网络质量实测（短名单评分 s=22.9，973 浏览 / 36 赞 / 20 回复；当天 Develop 分类里篇幅最完整的一篇硬核长文，正文 12,000 字）
- **解决痛点**：韩国家宽 / 落地机常被商家用「大带宽 2000Mbps」「原生家宽 IP」「AI 全解锁」一句话打包宣传，实际到中国大陆三网表现、CDN 命中、中转质量却高度不确定。作者 STALK 用一台官方提供的测试机（SKB-IPv4-Max）把「半优化」这个含糊定位拆成可复现的量化结论：4 vCPU / 4GB / 32GB NVMe（工单可免费升到 150GB）、2000Mbps、60TB/月仅出站、1 个 AS9318 IPv4、无 IPv6，原价 $123/月，注册需手机验证，被封可免费换 IP（7 天 2 次 / 30 天 4 次）。作者开篇即声明「本文无 AFF」，但测试机由 NexKr 官方提供，这一点读时需要计入。
- **技术要点与核心流程**：测评覆盖了三层。① **国内三网直连**：用 IPERF3 单线程从多地家宽打向目标机，结论是电信基本「全天个位数 Mbps + 高丢包」——广州电信 11% 丢包、单线程 419 Kbits/s~2.09 Mbits/s，杭州电信 9% 丢包 2.29 Mbits/s，湛江电信 8.5% 丢包 839 Kbits/s，武汉电信 11% 丢包 1.36 Mbits/s；联通 / 移动则「看脸」，广州移动 0.5% 丢包能到 261 Mbits/s、深圳联通 1% 丢包 254 Mbits/s，但广州联通机房 0% 丢包却只有 2.35 Mbits/s。② **国际 CDN 与中转**：Cloudflare / Akamai / Fastly 约 2ms 命中，而部分 Google 服务、CacheFly、Netflix API 常绕路日本、额外 30ms+，作者据此点出一个很实用的「**假延时**」现象——测速软件若选了 Google 系测速点，会把访问 CDN 的绕路算进 VPS 出口延时；中转方向，香港 30-60ms / 单线程 300-400Mbps、日本 30-40ms / 单线程约 700Mbps，六线程实测 FXTRANSIT.HK.T1 合计 1.76 Gbits/s、Gomami.JP 合计 1.62 Gbits/s，建议「日本为主」。③ **IP 质量与硬件**：上游直属 SK Broadband（AS9318），原生 IP + 常规流媒体 / AI 全家桶解锁 + 几乎无滥用标记，作者称「基本可以代表韩国家宽的顶端 IP 质量」；CPU 是较老的 Xeon Platinum 8272CL，4 核「够用」但与 EPYC Milan/Genoa、Ryzen 差距明显，磁盘读写是亮点，适合反代 / API / Docker / 个人博客 / 轻量数据库，不建议大型编译或游戏服。此外如实提示了韩国地区「送中」风险（独立 IP 只能缓解、无法完全避免），以及退款边界（未开通 / 商家持续故障 / 服务与合同显著不符可退，「不想用、买错、共享带宽速度不理想」不可退）。
- **价值总结与实践建议**：这篇的价值在于把「半优化」量化成了劝退表——电信用户直连基本不用考虑，联通 / 移动属于「开盲盒」，作者自己给的定位就是「**纯落地机**，前面挂香港 / 日本前置转发增加稳定性」。但也要如实指出讨论区的落差：高赞回复几乎全是「又来了 感谢测评」「捕捉到一个喵喵」「前排撸猫」这类灌水，没有一条对测试方法、单机样本或「测试机由商家提供」提出实质质疑或交叉验证；全部数据来自同一台测试机、同一时间段的单次测量，PT 时间、晚高峰表现、跨运营商长期稳定性都未覆盖。实践上建议把它当「选型线索」而非「性能承诺」：真要上生产，务必用自己的线路在目标时段复测 IPERF3 与丢包，把「送中」预案（换 IP 政策）和「$123/月 + 60TB 只适合大户」的成本账先算清；个人用户按作者建议去看 NAT / 特价产品更现实。
