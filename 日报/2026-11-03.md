### 2. [上海首例盗用 AI 算力案：400 多万注册用户薅积分，判三缓三](https://linux.do/t/topic/3114886)

- **核心分类**：前沿快讯 / 法律与合规
- **解决痛点**：主帖只有一句「搞国内公司可太野了吧」加媒体标题。这条之所以值得展开，是因为它**第一次把「算力是不是受法律保护的财产」写清楚了**，对做 API 中转、聚合、二次开发的佬友是直接相关的红线。
- **技术要点与核心流程**：核实上海市徐汇区检察院 / 上海法治报 / 澎湃 / 界面（11-2~11-3 报道）：2025 年 12 月，有技术基础的宗某某自学调用 AI 平台 API 的「教程」后，盯上一家大模型聚合平台（用户登录消耗积分生成图片视频，平台按次向上游模型厂商付算力成本）。他摸到平台**不对外开放的接口**，自建「中转网站」低价售卖 AI 绘图/视频生成服务，后台实际跑的全是那家平台的付费算力。公司发现旗下两款应用短时间内涌入 **400 多万个由同一 IP 注册的用户**——目的是批量领取新用户赠送积分、汇成「积分池」出售。攻防过程被检察官称为「用 AI 攻破 AI」：先用 AI 写自动化注册脚本、买大量邮箱批量注册**近 30 万个免费账号**组成账号池轮换调用；平台加 IP 注册限制后被绕过；今年 1 月平台新增**电子签名校验**，他又用 AI 写脚本自动伪造签名持续绕过。今年 3 月公司报案、宗某某被抓，至案发**非法调用接口 29 万余次、违法所得 3.4 万余元**。徐汇区法院以**非法获取计算机信息系统数据罪**判处**有期徒刑三年、缓刑三年，并处罚金 4 万元**。他辩解「浏览器里都能看到、也没加密，我以为都是公开的」，检察官指出平台从未对外提供 API 付费调用、用户协议明确禁止自动化抓取与绕过验证、其账号此前已被批量封禁，**「只是搬运接口」不是免责挡箭牌**。
- **价值总结与实践建议**：3706 浏览/146 赞/72 回复，@dabao 问「判三缓三是什么意思？到底是进去还是不进去」，@Vjian 答「应该是不进去，先观察三年，你要是老实就不进去，还不老实就进去」，@yyyb 则调侃「这也是能力，国家应该养起来」。三点必须讲清：① **标题里的「400 多万个账号」是媒体口径**——报道原文是「400 多万个由同一 IP 注册的用户」，而实际批量注册的账号池是「近 30 万个免费账号」，两个数字不是一回事，别照抄标题；② 检察官给的三条边界很实用：**接口调用必须获得正当授权**；对平台正式开放、分配密钥、约定计费的公开 API，即便超量欠费一般走民事/反不正当竞争；但**对未开放商用的私有接口主动逆向解析、伪造凭证、突破防护批量牟利**，就进入刑事评价范围；③ 结合 11-02 那篇「搞中转站一年」的经验帖看，社区里大量讨论的是 newapi/sub2api、码支付、双域名这套搭建术，**技术本身中性，界线在授权与是否突破防护**——这条判例正是给这套玩法划的线。本文只做事实记录，不构成法律意见。

### 3. [LucentThinker：用 DeepSeek 全家桶搭廉价 Deep Research](https://linux.do/t/topic/3114217)

- **核心分类**：开源工具 / Agent 研究助手
- **解决痛点**：作者 user1164 认为到 2026 年 11 月，OpenAI 的 Deep Research 已难满足需求 —— 他用「钙钛矿叠层组件商业化尽调」（要求把实验室小面积电池认证效率、大面积组件效率、产线产能、实际出货、户外运行分开比较，重点看牛津光伏/协鑫光电/纤纳光电，还要覆盖湿热紫外稳定性、封装与铅泄漏、良率、设备兼容、每瓦成本）实测，结果「并不丰富，来源较少，甚至没有清晰注明」；而效果更好的 MiroThinker 收费后太贵（最高档约 **20 美元/月仅能搜 10~20 个问题，单题 1~2 美元**）。
- **技术要点与核心流程**：作者复述的技术路线是「**小模型 + 多轮次搜索 > 大模型 + 寡轮次搜索**」：MiroThinker 通过后训练增加主模型的搜索意愿，每轮搜索后指出当前结果不足再继续下一轮，主模型基于 Qwen3-235B-A22B-Thinking-2507 微调，配合 SerpApi 与 Jina fetch 就超过 GPT-6 Pro + Deep Research。转折点是 **2026 年 10 月 DeepSeek 发布 search / fetch API**：价格 **5 元/1000 次调用**，比 Jina 和 SerpApi 便宜；fetch 成功率不高，但 search 有时直接返回 abstract 与 content，可当部分全文弥补 fetch；外网调用能返回外网结果，且访问国内网站不受限（SerpApi / Jina 有限制）。作者据此用 **DeepResearch flash V4.1 + DeepSeek search + fetch** 搭出 LucentThinker，称单次调用成本约 **1 元**。仓库 `XinYu-pumch/LucentThinker`，支持源码安装或在 DSH 中「插件 → 添加插件」填 `dsh-plugin-lucentthinker` 启用（macOS Apple Silicon / Windows x64）。评测方式：让 gpt-6 astra 出 10 个研究任务（能源、健康、软件、商业、职业、汽车、历史与贸易），对比 LucentThinker / MiroThinker deep / GPT Deep Research，按统一六维标准由 astra 打分，作者称「远超其余两个」；还特意用一个中国对外经济问题分别中英文提问，结果显示无偏差。
- **价值总结与实践建议**：379 浏览/49 赞/18 回复，热度不高但完成度不低；@AsherL1n「太高级了，不敢吱声，书签+1」，@LivelyDolphin21「看着就很专业的感觉」，作者自己则催「好家伙，没有大佬品评一下吗」。三条冷静提醒：① 那张评分表是**作者自拟六维标准、由模型当评委**的自评，不是第三方 benchmark，别当结论用；② 「5 元/1000 次」「单次约 1 元」是作者按自己调用量估的，**没给出 token 消耗明细**，成本要按自己的题目重算；③ 最值得借鉴的不是这个项目本身，而是那条**「每轮搜索后显式指出结果不足再继续搜」**的循环设计——这是可以迁移到任何 research agent 上的通用改进。用之前先拿自己领域的一道题跑一遍，比看评分表靠谱。

### 4. [paper-figure-to-figma：把任意科研图重建成可编辑矢量](https://linux.do/t/topic/3116157)

- **核心分类**：开源工具 / 科研绘图与 Agent Skill
- **解决痛点**：论文里的架构图、流程图想改成自己的版本，通常只能截图贴上去或照着手画一遍。作者 ykhhhh 把它做成一个 Agent skill，直接重建成 Figma 里**原生可编辑**的文字、曲线与渐变。
- **技术要点与核心流程**：仓库 `sidiangongyuan/paper-figure-to-figma`，输出可编辑 Figma 矢量并支持 SVG/PDF 导出，已用在作者自己的论文里。主帖一度「一直被删贴，不知道违反了啥规定」，具体内容被挪到回复与项目页，只留效果图：示例 **AgentThink = 59 个可编辑文字层 + 264 个矢量路径节点**，**PlanWAM = 43 个文字层 + 334 个矢量对象 + 8 处渐变**，曲线、渐变、颜色高度还原。作者在回复里补了流程细节：**结构与细节**（模块分组、训练/推理分支、跨区域箭头，以及渐变、曲线、虚线、文字底板都纳入重建与检查）、**原生可编辑图层**（文字直接改内容和字体，模块/箭头单独调，输入输出中的 RGB 图片保留为独立图片层）、**整图与局部双层复核**（从 Figma 导出实际结果与参考图对照，先修内容和连接关系，再处理局部外观与可读性）、**支持连续修改**（第一版后可继续提「放大副标题」「调整这条曲线」「保留其他区域」在同一画板迭代）、面向论文排版的默认设置（正文默认 Times New Roman）。后续想做 PPT/Draw.io 兼容和「一句话改风格」的风格迁移。作者也承认图标这类容易失真，「可以试试更好的模型，或者用 Figma 插件库重新添加小图标」。
- **价值总结与实践建议**：665 浏览/72 赞/25 回复，@ZWfat 的提问最实际：「支持将别人论文里的图转换成可编辑 svg 么，能的话借鉴别人的网络图的时候都不用自己吭哧吭哧画了」。三点提醒：① 「90% 以上还原度」是**作者自述、没有独立评测**，且他明说效果依赖模型、图标类仍易失真，别指望一键无损；② 价值不在「像」，而在**可编辑 + 可连续修改** —— 双层复核和「保留其他区域」这类约束，才是能把产出用进论文的关键；③ @ZWfat 那个用法要谨慎：把他人论文配图转成可编辑矢量，**技术可行不等于可以照搬**，学术引用与图版权需自行确认，至少应重绘并规范标注来源。

### 5. [老板提的 AI 需求，公司就我一个技术（菜）](https://linux.do/t/topic/3116169)

- **核心分类**：工程实践 / 需求与预期管理
- **解决痛点**：主帖只有两行需求，却把「老板认为 AI 万能、公司只有一个技术」的典型困境摆得很完整 —— 这是这几天里最接近很多人日常的一帖。
- **技术要点与核心流程**：楼主 yiyaweiwo 列的两个系统：① **小红书内容系统** —— 获取小红书全平台竞品笔记数据（图文、文案、视频），AI 分析后由 AI 生成一个新的竞品内容；② **视频生成系统** —— 获取广告平台的广告爆量素材，AI 分析后生成全新的爆量素材。拆开看，每个都是「**数据采集 → 结构化分析 → 生成 → 效果验证**」四段完整链路，且第一段（全平台竞品数据、广告平台爆量素材）本身就涉及平台反爬与数据合规，第三段（生成图文/视频）要接多模态模型与素材管线，第四段还需要投放回流才能闭环——**这不是接个 API 能交付的东西，是两条产品线**。
- **价值总结与实践建议**：1438 浏览/154 赞/81 回复，评论区全是同病相怜：@moonbird「我现在就在这样的公司，只有我一个技术，我还是刚毕业纯自己摸索，老板直接提需求，他认为 AI 是万能的，让我一天搞出来一个系统，还不能有 BUG」，@Wind0317「这个如果做成熟少于一千万我都不卖」，@guiqing「小公司想要攻克这么高级的嘛？不担心你这个技术直接自己做老板啊」。三条实操：① 先把需求**拆成可人工验收的单点**（比如给定 20 条竞品笔记，做人机协作的分析表 + 一版改写），用一周出可见结果，比承诺「全自动系统」稳得多；② **把数据获取的合规与反爬成本摆到台面上**，这是两个需求共同的硬约束，也是最容易在验收时爆雷的地方；③ 预期管理比技术更关键——明确写下「AI 生成不保证爆量」「需要人工审核」「不承诺无 BUG」，并让老板在范围与验收标准上签字。@moonbird 那句「一天搞出来还不能有 BUG」不是玩笑，是这类岗位最该先谈清楚的事。
