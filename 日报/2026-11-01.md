### 1. [Airsnip 轻截 0.7.0：1MB 的全功能截图软件](https://linux.do/t/topic/3103210)

- **核心分类**：开源工具 / Rust 桌面应用
- **解决痛点**：截图工具要么体积臃肿、待机也吃 CPU，要么标注功能太弱。作者用 Rust + 纯 CPU 渲染做了一个 1MB 的 Windows 截图标注工具，主打「待机 0% CPU」，把常用标注做全但保持极小体积。
- **技术要点与核心流程**：作者 Waviness6884 自述开发了一个半月、累计提交 86 次，仓库 `bd-dxg/airsnip`，官网 airsnip.bddxg.top。功能清单：矩形（Shift 画正方形、支持二次编辑、可拖成圆角）、**三次贝塞尔曲线箭头**（可弯曲绕开遮挡，双击恢复直线，代码片段场景好用）、文本（系统全部字体、粗斜体）、高斯模糊（作者明确说「就是马赛克，但高斯样式更好看，所以只做了高斯」）、荧光笔、聚光灯、长截图（带独立预览）。一个贯穿全局的交互特色：**把鼠标放在标注元素上滚滚轮即可改线宽／字号／模糊强度**，框选与标注都支持方向键 / Shift+方向键微调。设置面板支持开机自启、贴图位置（原位或屏幕居中）、自定义快捷键（F1/F3 为全局，进入截图后 1=矩形、2=箭头、3=文本、s=长截图，实时生效），保存支持 PNG / JPEG / **WebP 无损**、可直抄剪贴板，文件名模板可选时间戳或仅日期并记住上次目录。外观跟随系统深浅色主题。未来计划是渐变色矩形/箭头和通过 API 调用实现 OCR 翻译（**刻意不走本地以免撑大体积**）。主帖按社区规范附了开源推广申明，并说明 AI 润色内容以截图形式给出。
- **价值总结与实践建议**：2154 浏览/329 赞/157 回复，当时仓库只有 12 颗星。回复区的诉求高度集中在「对标谁」：@andyjiao15 直接问「能不能干翻 pixpin，破解版功能阉割了」，@li5bo5 追问 OCR 和翻译，@superInt 则想要 Snipaste 的贴图能力。三点判断：① 它的差异化不在功能多，而在**1MB / 纯 CPU / 待机 0%** 和滚轮调参这种手感细节，适合常驻后台、讨厌 Electron 截图工具的人；② **目前没有 OCR 与贴图**，这两项恰是 PixPin / Snipaste 的核心卖点，别被「全功能」三个字误导；③ 贴图、OCR 都在路线图外或靠 API，短期内更像是 Snipaste 的轻量替代而非平替。Windows 用户想尝鲜可以直接下，作者明确欢迎 Issues 反馈。

### 2. [ProxyCrab：10MB 干翻 Proxyman 的开源抓包工具](https://linux.do/t/topic/3104217)

- **核心分类**：开源工具 / 网络调试与 Agent 协作
- **解决痛点**：作者 yricky 把公司里用 Charles / Reqable 踩的坑列得很具体：Charles 只支持 HTTP(S)、WS 与 SSE 支持差、更新慢（Mac 上 Rosetta 跑 4.x）、历史抓包不被当作公司资产难管理，Map/Local/Rewrite 一堆概念没人搞得清生效时序；Reqable 虽然支持 Python 脚本和历史会话，但有关闭后端口不释放（重开自动 +1，得手动杀进程）、长时间抓包脚本编译缓存膨胀、免费版限制多等问题。更深一层是 **AI Agent 嵌入开发测试流程后，人和 Agent 拿到的不是同一套抓包能力、改动也无法互相同步**。
- **技术要点与核心流程**：基于 **Tauri + Vue 3**，MIT 开源免费，公司小组内已小范围试用数月。已实现：HTTP/HTTPS/**HTTP/2** 抓包，请求/响应/头/Body 查看，图片音视频预览、Protobuf/gRPC 结构查看，筛选排序、完整 Body 下载与 HAR 导出；请求调试支持编辑重发、**Lua 脚本**改请求响应、Mock、断点暂停执行临时脚本、限速超时、脚本执行历史与修改快照；WebSocket 双向消息时间轴、Lua 丢弃/发送/替换消息、追踪消息生成来源；自定义规则可用 Lua 提取业务字段生成自定义列、按 Session 配独立拦截器链与分流；Session 多开归档恢复、**只读链接分享（浏览器实时查看、重启后保留）**、读取时脱敏、导入导出。**最特别的是 Agent 协作层**：提供 HTTP API 与配套 Skill，外部 Agent 可分析流量、编写脚本和配置规则，操作结果同步回界面，并按接口配访问权限、桌面端支持人工审批。另支持 CLI 无界面运行 + 浏览器远程管理、CA 证书下载、Clash 订阅与二维码接入，以及 Base64/JWT/二维码/文本比对小工具；覆盖 macOS / Windows / Linux。作者特别注明：安装包大小、启动速度、内存占用**未做统一实测所以没列进对比表**，且 Linux 版因直接嵌 WebKit 偏大，后续考虑 Tauri-cef。
- **价值总结与实践建议**：1723 浏览/222 赞/59 回复，@justincnn 的反馈很典型「这个好，本来昨天还想着买 proxyman」，@wangcccccct 则提醒「如果是 AIGC 记得截图」（社区对 AI 生成内容的举证要求）。三条实操：① 如果你在 Charles / Proxyman 上纠结付费，**这张对比表不能当性能结论看**——作者自己承认体积/启动/内存没实测，标题里的「10MB」也未见正文给出测量口径；② 真正难被替代的是 **Session 只读分享 + 脱敏 + Agent API 审批**这一组，适合要把抓包结果交给同事或 Agent 复现的团队场景，而不只是个人调试；③ 用 Lua 而非 Python 做脚本扩展是有意选择（规避 Reqable 那套缓存膨胀），但既有 Python 脚本资产迁移成本要自己评估。

### 3. [ds-v4.1-flash-1017 / qwen-3.8 本地部署横向测试报告](https://linux.do/t/topic/3103315)

- **核心分类**：模型评测 / 本地部署
- **解决痛点**：作者 cainiao3hao 说得很直白——「大家关心的其实是能不能用、效果、差不多相当于什么云端大模型」，而不是量化参数。这篇把本地量化模型和一串云端型号放进同一套 harness 做盲测，回答的正是这个问题。
- **技术要点与核心流程**：本地环境 **9950X3D + DDR5 6400 64G + 5090 32G + 9100Pro 8T / P5800X 1.6T**；推理引擎分别为 Strata（Qwen-flash，commit 46c152a）、Xolotl base（DeepSeek，281afdada）、llama.cpp（Qwen-27B，ff018870）；为排除干扰**统一用 pi 1.4.0、无任何 extensions**，云端与本地都接 cpa 从请求监控采集中位数。三类题：① **融合糖果题**（把鹈鹕骑车 SVG 生成与抽屉原理糖果题缝在一起，测前端风格/注意力/agent）——盲测里 ds-v4.1f-1017 中位 59 tps、首字 1.034s、总耗时 13min，qwen-flash 136 tps / 1.020s / 14min，qwen-27b 45 tps / 0.241s / 19min；作者结论 **ds > qwen-flash > qwen-27b**，并指出两个 qwen 单独做糖果题都能解对，但融合进 SVG 任务后「手感可辨」这个条件被注意力分散掉而漏掉。② **世界地图**（16,200 个采样点、90×180 矩阵，禁联网禁地理库，测世界知识）——qwen-flash 以 139 tps 干了 36min、单轮 agent 产出 300 多 k，效果接近帖中称的 opus-5 / sonnet-5.5 档；ds 与帖中称的 gpt-5.6-sol 都「草草完事」，此题结论反过来是 **qwen-flash > deepseek**；qwen-27b 因必爆上下文、调高上下文后速度不可用而弃赛。③ **海龟汤**（测多轮稳定性与上下文腐烂，用三个评委模型共同评分）——ds 1 轮锁定答案（作者称此题在世界知识内、论外），qwen-flash 12 轮基本锁定、22 轮还原全部，评分 astra 7.0 / fable 8.0 / argon 9.2；qwen-27b 28 轮且后期需强提示，评分 3.5 / 5.0 / 7.0，扣分点在「自己挖坑自己跳、陷在之前的 thinking 里出不来」。
- **价值总结与实践建议**：2612 浏览/111 赞/65 回复，@W1nge「看完了，佬写的真好」，@gamespark「本地个人部署，爽用 ds 感觉也快了」。最有价值的是 @Yuuki_Yuki 的真实约束：**5070 显存太小，加到 96G 内存只能跑 qwen3.8-flash，ud_q4 只有 20+ 吐字**，想问 q2 的 ds 和 qwen 差多少——这恰好说明报告的 5090 32G 平台结论不能直接外推。三点提醒：① 文中出现的 gpt-6.x / claude-fable / gemini-4 等均为**帖中使用的型号称呼与社区盲测代号**，作者自己也强调是主观体感（「个人感觉」），不是官方 benchmark；② 结论高度依赖任务类型，糖果题 ds 赢、地图题 qwen 赢，别拿单一排名选模型；③ 真正可复用的方法是**统一 harness + 中位数 tps/首字延迟 + 盲测**，比单纯跑分更能反映 agent 场景下的实际体验。
