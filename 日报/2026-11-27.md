### 1. CC tricks：把 `/loop` 当巡检器、`/compact` 当重启键，窗口内浏览第一的两招
[https://linux.do/t/topic/3251696](https://linux.do/t/topic/3251696)

- **核心分类**：开发调优 / Agent Coding 流程与上下文管理（主帖 3251696：1,478 浏览 / 218 赞 / 33 回复，作者自述高强度使用 Claude Code 的个人技巧；发布于 11-26 21:29，本期才落回统计窗口内，上一期因窗口闭合更早被判为窗口外帖子）。本节所有命令、用量与效果均为作者自述，评论区只有附和与玩梗、没有独立复现，本报告不作效果背书。
- **解决痛点**：长时间挂着 Agent 跑任务时，SubAgent 和 Background Shell Task 在后台跑完就静默结束，人盯着会话看不出哪些已经完成、哪些卡住；而上下文打到七八十之后继续在旧会话里追加指令，缓存命中率和输出质量都会掉，直接开新会话又丢掉前面的决策脉络。作者要解的是"既不漏看后台任务、又不带着满负荷上下文继续跑"这两个具体动作。
- **技术要点与核心流程**：① **定时巡检**——`/loop 30m 检查是否有活动SubAgent 和 Background Shell Task, 逐个汇报`，让 Claude Code 每 30 分钟自动列一遍仍在活动的后台任务并逐个汇报，作者称这样"Cache效率拉满、咔咔省钱"；② **上下文重启**——上下文打满七八十又不想续旧会话时，切到 DeepSeek 配置用 `/compact` 压缩，再切回原模型，作者称效果相当于"纯净启动不丢脑"；③ **用量背景**——作者自述"一天 24 小时睡 3 小时火力全开、Opus 5.5 高达 5.5B 的燃烧率"，并说明是因为"Ultra 一个周限不够用、点了重置卡，不用完老烧心"，即技巧的出发点是额度管理而非能力增强；④ **评论区反应**——@stevessr「这样可以找回脑子」、@clx「看见哈雷就______」、@MindsRiverPonder「这就是哈雷的魔术技巧？」，没有第三方的效果对比或失败反馈。
- **价值总结与实践建议**：① 这两招的价值在"把后台任务显式化"，适合同时挂多个 Agent 任务、又不能一直盯屏的场景；② `/compact` 跨模型切换能否真正保住关键决策，取决于压缩摘要的质量，帖子只有一句"嚯嚯纯净启动不丢脑"、没有前后对照，**别把个人体感当通用结论**；③ 5.5B token/天是单个重度用户的自报用量，不能拿来推算一般成本；④ 评论区的"哈雷魔术技巧"玩梗说明多数人只是看热闹，真要照做建议先在小任务上验证一遍再上生产；⑤ 与 11-25 期精选 5 的 Agent Memory 四分类长文、11-26 期技术侧 3246251 H3Lite 工作流合看，这几条都在解"上下文与记忆怎么管"，但彼此没有互认，别拼成一套完整方法论。
