### 1. [开着代理，运营商可能还是知道你在看 YouTube：聊聊 Clash 的 DNS 泄露](https://linux.do/t/topic/3126047)

- **核心分类**：Develop / 代理配置与 DNS 隐私
- **解决痛点**：开着 Clash 看 YouTube，视频流量确实走了节点，运营商照样可能知道你访问了 www.youtube.com —— 原因很可能是配置文件里几处不起眼的写法，让本该交给代理的域名先在本地查了一次 DNS。作者说站里已有两帖（3029350、3082017）在聊这事，但大家对「DNS 泄露」的定义和危害程度都不一致，于是按 ClashMeta 最佳实践下了个明确定义：**需要进行代理访问的域名，不应该被任何直连 DNS 解析**。
- **技术要点与核心流程**：三层。① **检测**：browserleaks.com/dns、ipleak.net、dnsleaktest.com 让浏览器访问一批随机子域名，看是哪些 DNS 服务器来查询；但作者点出这些网站只看得到最终出口 IP、看不出这次查询是明文还是加密（`nameserver` 写明文 8.8.8.8，结果页显示 Google 的服务器看着正常，查询其实已明文过了一遍运营商），而且测的是它自己的随机域名，未必和你真正关心的网站走同一条规则。更可靠是 Wireshark 过滤 `dns` 抓包，访问 YouTube 看列表里有没有 youtube.com 的明文查询。② **谁能看到什么**：明文 8.8.8.8 / 223.5.5.5 / 114 → 路上所有人含运营商；国内 DoH（https://223.5.5.5/dns-query）→ 阿里腾讯能看到；境外 DoH 直连 → 境外服务商能看到；`https://1.1.1.1/dns-query#PROXY` 走代理 → 本地网络谁都看不到。顺带破了个常见说法：「把 DNS 改成 8.8.8.8 就不会泄露」解决的是污染，8.8.8.8 默认走明文 UDP 53，中间人照样看得见。③ **泄露主因与配法**：mihomo 规则自上而下匹配，IP 规则（GEOIP / IP-CIDR / IP 类规则集）必须先把域名解析成 IP 才能判断，而这次解析用的是 `dns.nameserver`、发生在还不知道流量走直连还是代理的时候，于是排在 IP 规则后面的代理域名会先被查一遍。解法是给 IP 规则加 `no-resolve`、或把 IP 规则全放到域名规则之后。系统代理下浏览器把域名交给 mihomo 自己不查；TUN 下应用会先自己查 DNS，需要 `dns-hijack: any:53` 或 `enhanced-mode: fake-ip`。Windows 还默认开着「智能多宿主名称解析」，会同时往所有网卡发查询，mihomo 只能拦到虚拟网卡那份——专业版走组策略禁用，家庭版用 `reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\DNSClient" /v DisableSmartNameResolution /t REG_DWORD /d 1 /f` 后重启。配置清单：`dns.enable: true`；nameserver 只放加密 DNS、别混明文；国内 DoH 用 IP 形式省掉解析 DoH 域名那一步；配 `proxy-server-nameserver`；用 `nameserver-policy` 代替 `fallback`；`MATCH,PROXY` 兜底。文末列了 8 类常见错误，包括 `GEOIP,CN,DIRECT,no-resolve` 兜底会让规则直接不生效、键名 `nameserver-police` 拼错时 mihomo 不报错直接忽略整段、以及改的不是客户端实际在用的那份配置（如 mihomo-party 的 `%APPDATA%\mihomo-party\work\config.yaml`）。作者还开源了离线检测工具 DNSnitch（`gxcuit/DNSnitch`）：不运行 mihomo、直接读配置文件分析，报告指到具体行号，Windows 上还能只读检查 TUN 与智能多宿主状态。
- **价值总结与实践建议**：1,355 浏览 / 59 赞 / 27 回复，热度不高但技术密度是当天最高的一帖。回复里 @Wahah 问「开 DoH 之后再配置一个 8.8.8.8 是不是就能避免泄露了」，作者直接回「配置 8.8.8.8 大概率会泄露」——正好印证正文那节：mihomo 会同时向组内所有服务器查询，混进一个明文 DNS，其他几个 DoH 就白配了。三点实操：① 先抓包再改配置，别只信检测网站的结果页，结果页显示 Google 的服务器也可能这次查询已经明文过了一遍运营商；② 最小改动是给所有 IP 规则加 `no-resolve` 并把它们移到域名规则之后，再检查 nameserver 里有没有混进明文 DNS；③ Windows + TUN 组合务必单独关掉智能多宿主名称解析，否则配置写得再好，物理网卡那份查询照样直发运营商。作者自己也留了口径分歧（「国内加密 DNS 算不算泄露」）并发起投票，别把这套定义当成唯一标准；主帖与文末工具已注明开源，配置片段与结论来自作者实测，照抄前先在副本上验证。
