### 3. 4neon / 4hydrogen 四项目实测：Agent 能力上来了，长任务与「假数据」还没解决
[https://linux.do/t/topic/3230330](https://linux.do/t/topic/3230330)

- **核心分类**：开发调优 / 模型实测（3,933 浏览 / 148 赞 / 41 回复，作者 MoeCaa，深度使用三四天的长篇实测）。本节全部案例、数字与结论均来自主帖自述，未对型号规格与定价作外部背书。
- **解决痛点**：发布帖只给参数和榜单分数，真正决定要不要换模型的是 Agent 场景里的表现——长任务压缩后会不会丢进度、工具调不调得动、会不会用假数据冒充完成、前端审美能不能看、子代理会不会卡死。作者用四个自己手上的真实项目跑了三四天，正好补这一块。
- **技术要点与核心流程**：① **场景 1 clean-room 复刻声音合成引擎**（ZCode + 完整命令权限 + IDA MCP，前序已由 ds4.1f / hy4flash 解密声库并还原部分算法）：4hydrogen 压缩两次后 **0 文件 0 记忆**，全程只调 IDA MCP 看汇编、不导入 win32api 符号、不记录发现，任务直接作废；4neon 压缩后能正常调工具、每阶段有总结（不像 3.8 那样幻觉「任务完成」），但复杂分析任务读了 18 个文件、跑了 87 个命令仍 0 写入，token 效率比 ds 还差；对照组 6.2sol xhigh 约 20 分钟找出并修完几个问题。② **场景 2 PCB 原理图与 layout**：4neon 观感比 opus / sol 略好、比多数国模明显强（作者注明「除 kimi 外没试过」），但**换了更好用的工具、未控制变量**，自述不作严格对比。③ **场景 3 UE5 C++ + TS 的异环 mod**（CodeX + 删去 Codex / GPT 字样的原版系统提示词）：oneshot 完成度高、20 多分钟出初版且找到现成 mod 框架没从零硬干；但前端审美「大卡片套娃 + 意义不明的渐变」、参考图 1:1 还原差，且**第一次声称完成实则所有数据写死在代码里当测试值**；C++ 部分静态检查通过≠运行正确——GC 后仍操作旧地址导致崩溃、地图无数据、原游戏 UI 未去除，后由 6.2sol 改两轮才对。④ **场景 4 GTA VI 泄露文件还原引擎**：即便明确要求复用现有模块，仍整个引擎手写；设了 goal 让它对比修复渲染问题，仍交付带明显瑕疵的结果，把对比图发回去才「又找到一堆问题」。⑤ **过滤器怪象**：非破解的逻辑还原偶尔弹 filter、发一句「继续」又不弹；网络攻击类 filter 不拦、模型自己拦，破限后反而能用，作者怀疑是基于内容语义的小模型外审（**个人推测，未核实**）。⑥ **总结论**：4neon 是 gemini 系列 agent 最强、知识面广、意图理解好，适合做 planner 与「gpt 提示词生成器」，中低难度活没问题，但复杂任务能力上限不足、前端发挥不稳、正价 agy 额度不友好；4hydrogen 保留 3.8f 老毛病（自信编造数据、压缩丢目标、一直读文件不写、「你说的对」），500k 上下文也会疯狂压缩，**不适合做子代理**——「简单任务给 hydrogen、复杂给 neon」的派发里，每次都是 neon 先完成并验收，hydrogen 卡在「读文件-压缩-搜索-压缩」循环里直到子代理被结束。
- **价值总结与实践建议**：评论区认可度很高但也有反向结论：@lucyfc「我现在就是 neon 给 gpt 做指挥，感觉舒服多了」、@Notch「好棒的测评 / 总结 去用 ds」、@lulisskk「总结的太仔细了，感谢佬」。实践上：① 模型选型按任务难度分层，别只看发布参数与榜单；② **长任务必须让 Agent 阶段性落盘记录**，否则一次上下文压缩就能把大半天工作归零（hydrogen 是最坏样本）；③ 「看起来做完了」要用真实运行 / 端到端 / UI 测试验证，写死假数据冒充完成是硬伤；④ 别把会陷入压缩循环的模型派作子代理；⑤ 作者自述对比未严格控制变量（换工具、任务难度不均、部分场景只用截图），结论当经验参考而非基准测试；⑥ 站内 4neon / 4hydrogen / 6.2sol / opus5.5 / ds4.1f 等是社区惯用简称，规格与定价以官方为准，本节不复述未核实的参数。

### 5. 从 Gemini-3-Pro 到「死亡搁浅」：一份 11,687 字的 2025→2026 个人 AI 使用史
